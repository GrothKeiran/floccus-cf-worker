# 更新服务与账号配置

## 更新已有部署

1. 备份 D1 和部署配置。备份包含书签、密码哈希与内部密钥，请保密保存。
2. 保留原 `DB` 绑定，确认 `USERNAME` / Secret `PASSWORD` 与现有账号的用户名、密码一致。
3. 更新 Worker 代码：控制台替换发布附件 `worker.mjs`，或更新源码后执行 `npm run deploy`。
4. 打开当前 Worker 的 `/init`，程序自动应用新增迁移并记录环境配置管理的账号 ID。
5. 配置一致时保持原密码哈希、会话和应用密码有效，书签与同步状态保留。

数据库结构由 `/init` 处理，无需手工导入 SQL。原 v0.1/v0.2 用户仍需保留原内部 Secrets，直到它们成功迁入 D1，详见[内部密钥迁移](UPGRADE-0.3.md)。

如果旧库缺少账号关联，页面会提示先用原账号的当前用户名和密码完成一次关联。请先恢复对应变量并部署、访问 `/init`；关联成功后再修改账号信息。程序不会任意挑选一个用户来覆盖。

## 修改用户名或密码

1. 修改 Worker 的 `USERNAME` 或 Secret `PASSWORD`。
2. 保存并部署新配置。
3. 访问当前正式 Worker 的 `/init`。
4. 编辑现有 Floccus 同步配置，填写新的用户名和密码，保留服务器地址和书签文件名。

程序更新原账号而非创建另一个账号，原账号内部 ID、书签、节点及同步状态保持不变。账号配置变化会撤销原会话、应用密码、同步锁和临时上传。使用独立应用密码的浏览器应重新签发凭证；配置不变重复访问不会撤销凭证。

新用户名已被占用时返回错误，原账号和数据保持不变。关联账号已删除时不会重建账号或接管其他用户。`/init` 只使用 Worker 中的配置，URL参数或请求体不能用来指定新账号。

请在当前正式部署操作。访问历史或回滚部署的 `/init` 会应用该部署中的配置，操作前应确认变量值。使用管理员 API 单独重置密码后，应同步修改 Worker Secret，避免后续重新应用旧密码。
