# 升级到 v0.3.0：不导入 SQL，迁移旧密钥后只保留账号密码

> 本文保留对应历史版本的迁移说明；当前账号配置与升级流程请看[更新服务与账号配置](UPGRADE-0.5.md)。

新空库直接按部署教程配置 `USERNAME`、Secret `PASSWORD` 和 `DB`，然后访问 `/init`。以下仅针对已有 v0.1/v0.2 数据的用户。

## 1. 备份，先保留原 Secrets

备份 D1 和原有 `TOKEN_PEPPER`、`ADMIN_TOKEN`。**先不要删除或更换它们**，旧设备凭证摘要依赖原 Pepper，丢掉后不能从摘要反推出它。

## 2. 更新 Worker

控制台用户替换新版 `worker.mjs`；Wrangler 用户更新源码后部署。保留原 `DB` 绑定，不创建新数据库，不清空书签或同步缓存。

不需要手动执行新迁移 SQL。

## 3. 访问 /init

程序会自动按迁移记录补齐表，并把旧内部密钥保存到 D1 的私有配置表。已有账号、密码哈希、应用密码摘要和书签不变。

若提示 `legacy_pepper_required`，说明旧密钥还没有迁入 D1 就被移除了：先恢复原值再访问，不能随机生成一份替代。若提示密钥冲突，先核对备份，程序会停止而不是擅自覆盖。

## 4. 精简 Worker 的变量

确认初始化成功后，可以删除 Worker 中旧的 `ADMIN_TOKEN`、`TOKEN_PEPPER` 和 `BOOTSTRAP_*`。默认限制、注册关闭等均已内置，普通用户不需 MAX_* 或其他配置。

只保留自己的：

- 普通变量 `USERNAME`。
- Secret `PASSWORD`。
- D1 资源绑定 `DB`。

**已有账号不会被新的变量重置。** 请使用原账户密码登录 `/admin`；为与已有账号一致，可以把两个变量设为原用户名和原账户密码。原有 Floccus 设备密码继续使用。

不再强制配置 Cron；程序有请求触发的清理。已有 Cron 可保留，不影响正常同步。

## 5. 以后升级

先备份，再更新代码，访问 `/init` 自动应用新增迁移。不要导入旧初始化 SQL，也不要编辑已应用的迁移。D1 备份现在包含内部安全密钥，必须当作高敏感文件保护，不能公开上传 GitHub。
