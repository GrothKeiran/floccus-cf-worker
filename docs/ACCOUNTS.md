# 账号来自 Worker 的两个变量，不需要手工修改 D1

## 首次使用

只在 Worker 设置：

| 名称 | 类型 | 内容 |
|---|---|---|
| `USERNAME` | Text | 自己的用户名，例如 `owner` |
| `PASSWORD` | Secret | 自己的强账户密码，14～256字符 |

将 D1 以 `DB` 绑定后，访问自己的 **`/init`**。程序会自动建全部表，并读取这两个变量，将账号和密码哈希写入用户表。

**不需要注册 API、CLI、PowerShell、导入 SQL，也不需要设置其他 Secret。** 密码不会以明文保存，内部凭证密钥由程序自动生成并保存在 D1。

初始化只会创建新空库的初始账号；已有账号不会覆盖。重新部署和重复访问 `/init` 不重置密码，删除初始账号也不会自动重建。修改 Worker 变量不是恢复已有账号密码的方法。

## 登录网页，为浏览器生成应用密码

1. 打开自己的 **`/admin`**。
2. 用初始化进表的用户名和账户密码登录。
3. 在“添加一个浏览器”填写设备名，例如 `Chrome-电脑A`，点击“生成应用密码”。
4. 把显示的 WebDAV URL、用户名和 `app_…` 应用密码复制到该浏览器的 Floccus。
5. 另一台浏览器再生成一份，不需要在 Worker 中新增其他变量。

| 密码 | 用途 |
|---|---|
| Worker 中设置、初始化进 D1 的 `PASSWORD` | 登录 `/admin` 管理自己的设备 |
| 网页生成的 `applicationPassword`（`app_…`） | 填进某台浏览器的 Floccus |

每台浏览器独立应用密码，可以单独撤销，锁也能区分设备。应用密码仅签发时显示一次，丢失后撤销并重新生成。网页会话仅在页面内存中保存，刷新或关闭需要重新登录，不存 Cookie/localStorage/sessionStorage。

网页还支持查看设备、撤销设备、导出本账号备份和退出登录。导出文件包含书签和状态，请妥善保存。

## 旧版用户

从 v0.1/v0.2 升级时，保留原内部 Secrets，更新代码再访问 `/init`。程序保留原账号密码和设备凭证，并把旧内部密钥迁入 D1；成功后可以删除多余的 Worker Secrets，只保留自己的用户名密码配置。见[升级教程](UPGRADE-0.3.md)。

`BOOTSTRAP_USERNAME`、`BOOTSTRAP_PASSWORD` 只是旧版兼容别名，新部署不需要填写。

## 高级管理接口

原有管理 API 与 `scripts/client.mjs` 继续兼容。内部管理密钥默认生成在 D1，不通过网页或初始化响应返回；显式设置旧 `ADMIN_TOKEN` 的高级部署仍可使用原管理 CLI。**普通使用不需要知道或手动设置它。**

管理员恢复密码是单独的高权限操作，会撤销该用户原会话和设备密码，不是日常改环境变量。不要为恢复密码而删库或清空账号表。
