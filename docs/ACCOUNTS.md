# 同一组账号密码：Worker 设置，Floccus 直接填写

## 首次使用

只在 Worker 设置：

| 名称 | 类型 | 内容 |
|---|---|---|
| `USERNAME` | Text | 自己的用户名，例如 `owner` |
| `PASSWORD` | Secret | 自己的强密码，14～256 字符 |

将 D1 以 `DB` 绑定后，访问自己的 **`/init`**。程序自动创建全部表，并把这两个变量中的账号和密码哈希写入 D1。

**不需要注册 API、CLI、PowerShell、导入 SQL，也不需要设置其他 Secret。** 密码只保存带随机盐的 scrypt 哈希；内部密钥自动生成并持久保存在 D1。

## Floccus 直接填写同一个 PASSWORD

| Floccus 配置项 | 内容 |
|---|---|
| 后端 | WebDAV / 自定义服务器 |
| URL | 自己的 HTTPS Worker 域名 + `/dav/` |
| 用户名 | Worker 中设置的 `USERNAME` |
| 认证密码（第一个密码框） | Worker 中设置的同一个 `PASSWORD` |
| 文件名 | `bookmarks.xbel` |
| 文件类型 | XBEL |
| 加密口令（第二个密码框） | **留空** |

**到这里即可同步，不需要先登录管理页或生成应用密码。** 多个浏览器可填写同一组账户密码。先完成第一台同步再配置下一台，保持双向合并及安全保护。目录映射等见 [Floccus 配置](FLOCCUS.md)。

初始化只创建新空库的初始账号；已有账号不会覆盖。重新部署、修改变量和重复访问 `/init` 都不是重置密码功能，也不会清空书签或重建删除的账号。已有账号始终按 D1 的当前密码哈希验证；若已通过管理员重置密码，Floccus 应填重置后的密码。

## 可选高级功能：独立应用密码

不需要单独撤销设备时，可以一直用账户密码。若需要单独撤销某台浏览器，或同出口/同浏览器下有并发配置，可选择：

1. 打开自己的 **`/admin`**，用账户密码登录。
2. 在“可选：独立应用密码”填写设备名，点击“生成应用密码”。
3. 仅将该浏览器 Floccus 的认证密码改为生成的 `app_…`，其他配置不变。
4. 其他设备可继续使用账户密码，或各生成一份独立应用密码。

应用密码只显示一次，丢失后撤销再生成。撤销应用密码不会撤销账户密码；要使账户密码失效，需管理员重置密码。重置会同时撤销该账号所有会话、应用密码和旧锁。

账户密码模式利用 Cloudflare IP 和 User-Agent 的 HMAC 区分常见客户端；这不是可靠唯一设备 ID。同出口、相同浏览器的多个配置可能无法区分，IP 切换也可能需要等待旧锁。不要盲目强制抢锁；严格区分设备时用可选独立应用密码。详细见[协议边界](PROTOCOL.md#共享账户密码与可选设备凭证)。

设备列表只显示显式签发的应用密码，不显示程序内部的短期同步上下文。网页还支持导出本账号备份和退出登录；会话仅存当前页面内存，不存 Cookie/localStorage/sessionStorage。备份包含书签和状态，请妥善保存。

## 旧版升级和管理 API

v0.3 用户更新 Worker 后访问 `/init`，即可用原账户密码连接。v0.1/v0.2 用户需先保留原内部 Secrets，更新代码访问 `/init`，将密钥迁入 D1 后再精简变量，见[升级教程](UPGRADE-0.3.md)。所有旧应用密码仍兼容，不强迫已有设备改配置。

`BOOTSTRAP_*` 只是旧版兼容别名。原管理 API 与 `scripts/client.mjs` 保留；内部管理密钥默认生成在 D1，不回传给网页。显式设置 `ADMIN_TOKEN` 的高级部署仍可使用管理 CLI，普通使用不需要设置它。恢复密码是单独高权限操作，不能为了恢复而删库。
